قواعد طلایی (فرمول‌های کلیدی)

طول فیلدها و ثبات‌ها

  • n بیت ⇐ 2n حالت؛ M حالت ⇐ ⌈log2M⌉ بیت. (۳۲ حالت ۵ بیت، ۱۰۰۰ حالت ۱۰ بیت)
  • فیلد کد عمل = ⌈log2(#ops)⌉؛ فیلد آدرس = ⌈log2(#units)⌉؛ فیلد ثبات = ⌈log2(#regs)⌉.
  • LMAR = LPC = طول آدرس حافظه = ⌈log2(#addressable units)⌉
  • LMBR = پهنای دسترسی (اگر گفته نشده = طول کلمه)
  • LIR = طول بلندترین قالب دستور؛ LACC = LR = طول کلمه.
  • معمولاً: واحد آدرس‌پذیر ≤ کلمه ≤ پهنای دسترسی؛ اگر چیزی گفته نشده، هر سه برابرند.

آدرس‌ها و گام‌ها

  • طول دستور بر حسب واحد = (بیت‌های دستور) / (بیت‌های واحد) ⇐ گام شمارندهٔ مکان (LC).
  • کلمه بر حسب واحد k = w/u ⇐ گام اشاره‌گر آرایه = k؛ آرایهٔ N عنصری = N·k واحد؛ آخرین عنصر = base + (N−1)·k.
  • حافظهٔ بایتی + کلمهٔ ۱۶ بیتی ⇐ گام 2؛ کلمهٔ ۳۲ بیتی ⇐ گام 4؛ حافظهٔ نیبلی (۴ بیتی) + کلمهٔ ۱۶ بیتی ⇐ گام 4.
  • پرش نسبی: d = target − (addrjump + lenjump)؛ منفی ⇐ 2k − |d| (۸ بیت: 100h − |d|)؛ بازهٔ ۸ بیتی −128…+127.
  • بانک در حافظهٔ k بانکی: bank = a mod k، row = ⌊a/k⌋. کلمهٔ هم‌تراز: a mod k = 0.
  • قطعه‌ای: PA = (SR) + LA؛ صفحه‌ای: PA = (PR) ‖ LA؛ نسبی: EA = (PC) + d؛ شاخص‌دار: EA = addr + (Rx).

حافظه و نمادگذاری

تعریف‌ها

  • حافظه: آرایهٔ خانه‌ها با آدرس 0 تا M−1. دسترسی با MAR (آدرس ← رمزگشا) و MBR/MDR (داده) و سیگنال‌های Read/Write.
  • نوشتن: MAR ← a; MBR ← data; Write. خواندن: MAR ← a; Read ⇒ MBR ← (M(MAR)).
  • واحد آدرس‌پذیر: کوچک‌ترین گروه بیتی با آدرس یکتا (معمولاً ۸ بیت). کلمه: طول عملوندهای پردازش‌شده توسط CPU (ماشین n بیتی). پهنای دسترسی: بیت‌های جابه‌جاشده در یک دسترسی.
  • هم‌تراز: آدرس کلمه مضرب طول آن ⇐ یک دسترسی ☺. ناهم‌تراز: هر آدرسی ⇐ ممکن است دو دسترسی ☹ (وقتی کلمه از مرز سطر بگذرد).
  • Big Endian: بایت پرارزش در آدرس کوچک‌تر (IBM 360/370 و ماشین‌های درس). Little Endian: بایت کم‌ارزش در آدرس کوچک‌تر (Intel x86، RISC-V).

نمادگذاری و نمونه

Ma = خانهٔ a؛ (Ma) = محتوای آن؛ M(Ma) = خانه‌ای که آدرسش محتوای a است؛ A ← B = نوشتن. پرانتز دور ثبات = محتوای ثبات.

حافظهٔ اسلاید (آدرس 0..15): 10 11 21 31 14 1010 61 17 81 91 110 111 1120 131 114 115

  • (M9) = 91؛ M(M0) = M10؛ (M(M1)) = (M11) = 111
  • M(M0) ← (M0) + (M(M4)) ⇒ M10 ← 10 + 114 = 124

حافظهٔ ۴ بانکی (بایتی، کلمهٔ ۳۲ بیتی، ۲۱۶ بایت)

MAR ۱۶ بیت: ۱۴ بیت پرارزش ⇐ رمزگشای سطر (214 کلمه)، ۲ بیت کم‌ارزش ⇐ انتخاب بانک؛ MBR ۳۲ بیت (۴×۸). مثال: 1235h = …0100 1000 1101|01 ⇒ بانک 1، سطر 048Dh = 1165. کلمه از آدرس 5 ⇒ بایت‌های 5..8 ⇒ سطرهای 1 و 2 ⇒ دو دسترسی.

قالب دستور، کد عمل و مسیرهای داخلی

دستور = عمل (Opcode) + عملوندها (فاعل همیشه CPU است و ذکر نمی‌شود). ماشین n آدرسه: OpcodeOp 1…Op n

کد عمل می‌تواند نشان دهد: ۱) نوع عمل ۲) تعداد عملوندها ۳) طول دستور (اگر چند قالب) ۴) نوع عملوندها (صحیح/حقیقی/علامت‌دار) ۵) طول عملوندها ۶) روش آدرس‌دهی.

کد عمل گسترش‌پذیر (ماشین ۵): ۴ بیت اول 1111 ⇐ ۶ بیت بعد هم جزو کد عمل است.

مسیرهای داخلی ماشین

۱واکشی دستور: حافظه ← CU۴دادهٔ بی‌واسطه: CU ← ALU
۲دسترسی داده: حافظه ⇄ ALU۵I/O از طریق CPU
۳فرمان/وضعیت: CU ⇄ ALU۶I/O با DMA (بدون CPU)

نمونه: اجرای sub num1,num2 در ماشین ۱ ⇒ مسیر ۱ (واکشی)، ۲ (خواندن M15)، ۲ (خواندن M10)، ۳ (فرمان تفریق)، ۲ (نوشتن M15).

رمزگشایی و کدگذاری در ماشین ۱ (op 2 | a1 7 | a2 7)

01 0001111 0001010 ⇐ sub، a1=15، a2=10 ⇐ M15 ← (M15) − (M10) = sub num1,num2. add 3,100 ⇐ 00 0000011 1100100 = 01E4h؛ A1B5h = 10 1000011 0110101 ⇐ M67 ← (M53).

ثبات‌ها و چرخهٔ واکشی

  • ثبات n بیتی = n فلیپ‌فلاپ با کنترل گروهی (کلاک مشترک).
  • PIPO (ورود و خروج موازی؛ ثبات‌های معمولی)، SIPO (سریال← موازی؛ گیرنده)، PISO (موازی← سریال؛ با MUX و Load/Shift')، SISO (خط تأخیر n کلاکی).
  • یکپارچه (Register File): مثل حافظهٔ کوچک با رمزگشا ⇐ هر لحظه یک ثبات. مجزا (Isolated): خطوط جدا ⇐ دسترسی موازی.
  • آدرس‌پذیر (R0–R15 در IBM 360، AX/BX/… در 8086) / غیرآدرس‌پذیر (MAR، MBR، IR، PC).
  • همه‌منظوره (R0–R15 در 360) / خاص‌منظوره (CX شمارش حلقه، DX ضرب/تقسیم/I/O در 8086).
  • MAR آدرس سیکل حافظه؛ MBR دادهٔ مبادله؛ IR دستور واکشی‌شده؛ PC آدرس دستور بعدی.

واکشی: MAR ← (PC); MBR ← (M(MAR)); IR ← (MBR); PC ← (PC) + len ⇐ رمزگشایی ⇐ خواندن عملوندها ⇐ اجرا ⇐ نوشتن نتیجه. PC هنگام اجرا به دستور بعد اشاره می‌کند.

SIPO با ورودی 1,0,1,1: 1000 → 0100 → 1010 → 1101 (Q3..Q0). PISO با 1011: خروجی سریال 1,1,0,1 (اول LSB).

روش گام‌به‌گام ترجمه به کد ماشین

  1. طول هر قالب را بر حسب واحد آدرس‌پذیر حساب کن (بایت یا نیبل).
  2. گذر ۱: LC = مقدار org. برای هر خط: آدرس = LC؛ برچسب را در جدول نمادها ثبت کن؛ LC += طول (دستور یا dw = یک کلمه؛ dw N dup(?) = N کلمه). داده‌ها معمولاً بعد از کد می‌آیند.
  3. گذر ۲: برای هر دستور: کد عمل ‖ فیلدها (آدرس از جدول نمادها) ⇐ بیت‌ها را پشت‌سرهم بنویس و چهارتا چهارتا هگز کن (مخصوصاً وقتی فیلدها مضرب ۴ نیستند، مثل ماشین ۵).
  4. پرش نسبی: d = target − next؛ منفی را مکمل دو کن؛ اگر در بازه نیست از پرش مطلق (jmpl) استفاده کن.
  5. مقدار اولیهٔ داده‌ها: dw array = آدرس array؛ dw ? = ????؛ عدد منفی = مکمل دو (‎−1 = FFFF/FFFFFFFF).
  6. در پایان برنامه کنترل را به OS برگردان (وگرنه CPU داده‌ها را به عنوان دستور اجرا می‌کند).

loop: load (p1) ; store sum
      load (p2) ; add sum
      store (p3)          ; A[i+2]=A[i]+A[i+1]

      add #4 ; store p2 ; add #4 ; store p3

پشته‌ای (ماشین ۶)

push x ; push y ; add ; pop x   ; x = x+y
sp++                            ; x back on top
push counter ; push #1 ; sub
pop counter ; sp++              ; [counter]
push #loop ; jnz                ; cond, then target

ترفند: pop x داده را پاک نمی‌کند ⇒ pop x / sp++ = ذخیره بدون برداشتن (dup ندارد). اتحاد: ΣF0..n−1 = Fn+1 − 1 ⇒ برنامهٔ کوتاه‌تر.

ترفندهای کوچک

  • جابه‌جایی بدون متغیر کمکی: xor x,y / xor y,x / xor x,y.
  • صفر کردن: xor R,R یا sub x,x. دو برابر: add r,r. ضرب در ۴: دو بار add.

ماشین پشته‌ای و نمادگذاری لهستانی

  • پشتهٔ سخت‌افزاری LIFO داخل CPU؛ SP به جای خالی بعدی اشاره می‌کند (SP=0 یعنی خالی).
  • push x: Stack(SP) ← x; SP ← SP+1   pop: SP ← SP−1; return Stack(SP)
  • تابع: pop t1; pop t2; t3 ← func(t1,t2); push t3. تفریق/تقسیم: پایینی − بالایی (اول a بعد b ⇒ a−b).

علامت-مقدار (SM)

جمع A+B: اگر As=Bs ⇒ (As | Am+Bm)؛ وگرنه بزرگ منهای کوچک با علامت بزرگ‌تر:

As=1, Am<Bm → (0 | Bm−Am)As=1, Am>Bm → (1 | Am−Bm)
As=0, Am<Bm → (1 | Bm−Am)As=0, Am>Bm → (0 | Am−Bm)

تفریق: شرط اول As≠Bs ⇒ (As | Am+Bm)، بقیه همان. ضرب/تقسیم: (As⊕Bs | Am×Bm). جمع/تفریق SM پیچیده‌تر و پرسخت‌افزارتر از مکمل‌هاست.

مثال‌ها (۸ بیت): 00110100 = +52، 10010011 = −19؛ منفی 00100001 = 10100001.

مکمل یک و مکمل دو

  • مکمل یک: −x = 2n−x−1؛ −12 = 11110011 (۸ بیت). جمع: نقلی خروجی MSB به نتیجه اضافه شود.
  • مکمل دو: −x = 2n−x = مکمل یک + 1؛ −12 = 11110100. میان‌بر: از راست تا اولین 1 کپی، بقیه معکوس. جمع: نقلی دور ریخته شود.
  • تفریق: A − B = A + (−B).
  • سریع ۸ بیتی: −1=FF −2=FE −8=F8 −10=F6 −16=F0 −100=9C −127=81 −128=80؛ ۱۶ بیتی: −1=FFFF −200=FF38.
  • کسری: 01011.011 SM ⇒ 11011.011؛ 1s ⇒ 11000.010 → 00111.101؛ 2s ⇒ 01001.011 → 10110.101 (افزودن 1 به LSB).

اثبات‌ها (تکلیف): جمع‌کنندهٔ دودویی

مکمل یک: افزودن نقلی چرخشی = کم کردن 2n−1. حالت‌ها: ‎(+,+) بی‌نقلی ✓؛ ‎(+,−): R=(2n−1)+(A−|B|)؛ اگر A>|B| نقلی ⇒ A−|B| ✓؛ وگرنه 2n−1−(|B|−A) ✓؛ ‎(−,−): 2n−|A|−1+2n−|B|−1 = 2n+2n−(|A|+|B|)−2، نقلی ⇒ 2n−(|A|+|B|)−1 ✓.

مکمل دو: جمع‌کننده (a+b) mod 2n. ‎(+,−): 2n+(A−|B|) ✓ هر دو حالت؛ ‎(−,−): 2n+2n−(|A|+|B|) ⇒ دور ریختن ⇒ 2n−(|A|+|B|) ✓. سرریز: (+,+) ⇒ Cout=0، نتیجهٔ منفی یعنی Cin=1؛ (−,−) ⇒ Cout=1، نتیجهٔ مثبت یعنی Cin=0.

نمایش افزونی (Excess-K)

کد = مقدار + K؛ توزیع یکنواخت با K = 2n−1 یا 2n−1−1 (۴ بیت: Excess-8 یا 7؛ ۳ بیت: Excess-4 ⇒ 000=−4 … 111=3). K دیگر ⇒ ناهمسان (Excess-5 در ۴ بیت: −5…+10). Excess-2n−1 = مکمل دو با MSB معکوس. Excess-127: −20 → 01101011، 10000101 → 6.

  • نسبی: بیشتر پرش‌ها نزدیک‌اند ⇒ به‌جای آدرس کامل، جابه‌جایی کوتاه (بیت کمتر). اسمبلر d را از آدرس مقصد و محل فعلی می‌سازد. کد فقط با پرش نسبی مستقل از مکان است. jcxz loop_addr (8086، d هشت بیتی).
  • قطعه‌ای: آدرس فیزیکی = آدرس منطقی + ثبات قطعه. مثبت: OS (پیونددهنده/بارکننده) دردسر کمتر، کد تغییر نمی‌کند. منفی: یک جمع برای هر دسترسی ⇒ اجرای کندتر. (8086: seg×16 + off)
  • صفحه‌ای: صفحه 2P کلمه، حافظه 2M ⇒ ثبات صفحه M−P بیت، آدرس منطقی P بیت، 2M−P صفحه. مثبت: بدون جمع (فقط الحاق) ⇒ مزایای قطعه‌ای بدون عیبش. منفی: شروع فقط در مضرب 2P، حداقل طول 2P، برنامهٔ بزرگ‌تر ⇒ چند صفحه، مدیریت دشوار.
  • صفحه‌ای: حافظه 216، صفحه 1024، PR=000101، LA=0A3h ⇒ 000101‖0010100011 = 14A3h.
  • حافظه 220، صفحهٔ 4K ⇒ PR ۸ بیت، LA ۱۲ بیت، ۲۵۶ صفحه؛ برنامهٔ 10K ⇒ ۳ صفحه، ۲K هدر.
  • قطعه‌ای: 0003A000h + 00001234h = 0003B234h؛ صفحهٔ 64K با PR=0003h ⇒ 00031234h.
  • SR=00050000h، load (p) با p=16Fh و (p)=17Fh ⇒ دسترسی به 5016Fh سپس 5017Fh.

فون‌نویمان، فلین و ابررایانه‌ها

  • فون‌نویمان (۱۹۴۵): برنامه و داده در یک حافظه؛ CPU = CU + ALU؛ ورودی/خروجی؛ چرخهٔ واکشی–رمزگشایی–اجرا. گلوگاه: یک مسیر CPU–حافظه، یک دستور در لحظه ⇒ ساختارهای پیشرفته برای بهبود کارایی.

پرسش‌های تشریحی با پاسخ کوتاه

  1. مدل برنامهٔ ذخیره‌شده؟ برنامه و داده در یک حافظه؛ اجرای برنامهٔ دیگر فقط با بار کردن آن (بدون سیم‌کشی دوباره).
  2. چرا زبان اسمبلی؟ حافظه و زمان کمتر، کارهای وابسته به سخت‌افزار، کارهای حساس به زمان، ISR و برنامه‌های مقیم؛ (شکستن قفل و ویروس). دانش رابط با OS/BIOS، نمایش داده، دسترسی به دستور/داده/I/O.
  3. چرا اسمبلر دوگذره است؟ ارجاع رو به جلو؛ گذر ۱ جدول نمادها، گذر ۲ کد.
  4. اگر بعد از حلقه به OS برنگردیم؟ PC به داده‌ها می‌رسد و CPU آن‌ها را دستور فرض می‌کند ⇒ رفتار نامعلوم.
  5. مزایا و معایب کد خودتغییرده؟ خوب برای رمزنگاری و قفل نرم‌افزاری؛ بد از نظر مهندسی نرم‌افزار و نتیجهٔ غلط در اجرای چندباره.
  6. چرا آدرس‌دهی نسبی؟ پرش‌ها نزدیک‌اند ⇒ فیلد کوتاه‌تر، دستور کوتاه‌تر؛ کد مستقل از مکان.
  7. قطعه‌ای در برابر صفحه‌ای؟ قطعه: جمع (کند) ولی انعطاف؛ صفحه: الحاق (سریع) ولی مرز و طول ثابت.
  8. مشکل بارکنندهٔ جابه‌جاکننده؟ تشخیص آدرس از عدد در فیلدهای بی‌واسطه و اشاره‌گرهای داده.
  9. تعویض متن چیست و چرا مهم است؟ ذخیره/بار ثبات‌های کاربر؛ هزینه‌بر ⇒ برش زمانی بزرگ‌تر.
  10. چرا مکمل دو رایج است؟ یک صفر، جمع‌کنندهٔ ساده (بی‌نقلی چرخشی)، تفریق = جمع با مکمل.
  11. چرا جمع SM سخت است؟ مقایسهٔ اندازه‌ها، جمع‌کننده و تفریق‌کننده، انتخاب علامت.
  12. چرا 0.1 دقیق نیست؟ بسط دودویی متناوب است؛ اعداد حقیقی تقریبی‌اند چون بیت‌ها محدودند.
  13. نقش ثبات‌های MAR/MBR/IR/PC؟ بخش ۴.
  14. MISD چرا محل اختلاف است؟ بعضی می‌گویند ماشین واقعی ندارد؛ بعضی خط لوله و سیستولیک را MISD می‌دانند.
  15. نمادگذاری لهستانی چرا؟ بدون پرانتز/اولویت، مستقیم روی پشته محاسبه می‌شود.
  16. فرق Register File و Isolated؟ یکی در هر لحظه / دسترسی موازی.
  17. فایدهٔ نگهبان؟ حذف بررسی مرز در حلقه (کد ساده‌تر و سریع‌تر).

تله‌های امتحانی و خطاهای اسلاید

  • jpos: در ماشین‌های ۳، ۴ و تک‌آدرسه > 0؛ در ماشین ۷ ≥ 0.
  • جابه‌جایی نسبی از دستور بعدی حساب می‌شود، نه از خود پرش.
  • حافظهٔ نیبلی (ماشین ۴ و تک‌آدرسه): آدرس‌ها بر حسب ۴ بیت؛ هر رقم هگز یک واحد؛ کلمه = ۴ واحد.
  • ماشین ۲ پرش ندارد (باز کردن حلقه)؛ ماشین ۳ بی‌واسطه و پرش غیرشرطی ندارد (ثابت‌ها در حافظه).
  • MBR = پهنای دسترسی، نه واحد آدرس‌پذیر؛ IR = بلندترین قالب؛ PC = MAR.
  • pop داده را پاک نمی‌کند؛ در ماشین ۶ اول شرط بعد آدرس مقصد push می‌شود؛ sub = پایینی − بالایی.
  • ثابت منفی در دستور: مکمل دو با طول فیلد (‎−1 = FFFF در ۱۶ بیت).
  • در مکمل دو، −(−2n−1) قابل نمایش نیست (سرریز). جمع دو عدد ناهم‌علامت هرگز سرریز نمی‌کند.
  • FP: هم‌ترازی به سمت نمای بزرگ‌تر؛ مانتیس بریده می‌شود (نه گرد) در قالب اسلاید؛ نتیجهٔ صفر ⇒ نما صفر.
  • IEEE: نمای تمام‌صفر یعنی 2−126 و 0.F (نه 1.F و نه 2−127).
  • جمع BCD: +6 برای رقم > 9 یا نقلی.
  • کلمهٔ ناهم‌تراز که از مرز سطر بگذرد ⇒ دو دسترسی.
