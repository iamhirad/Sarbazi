آدرس‌دهی ضمنی (Implied / Inherent)

در این روش هیچ چیزی دربارهٔ عملوند در IF نیامده است، اما CPU می‌داند عملوند کجاست؛ محل عملوند جزو تعریف خود دستور است.

مثال‌ها
  • دستور loop address در پردازندهٔ 8086/88: cx ← (cx) − 1; if (cx) ≠ 0 then PC ← address. ثبات cx در دستور نیامده ولی ضمناً استفاده می‌شود.
  • دستور ضرب ثباتی MR 2,4 در خانوادهٔ IBM 360: R2:R3 ← (R3) × (R4). حاصل ۶۴ بیتی در جفت ثبات R2:R3 قرار می‌گیرد؛ R3 (عملوند اول) در دستور نیامده و ضمنی است.

ماشین تک‌آدرسه (ماشین انباره‌ای)

در ماشین تک‌آدرسه یکی از عملوندها همیشه در یک ثبات خاص‌منظوره به نام ACC (انباره، Accumulator) نگه داشته می‌شود و به صورت ضمنی آدرس‌دهی می‌شود؛ بنابراین هر دستور فقط یک فیلد آدرس دارد.

مشخصات ماشین نمونهٔ تک‌آدرسه
  • حافظهٔ اصلی: 216 واحد آدرس‌پذیر (هر کدام ۴ بیت)؛ کلمه ۱۶ بیت (ناهم‌تراز، Big Endian)؛
  • روش‌های آدرس‌دهی: ضمنی، مستقیم، غیرمستقیم و بی‌واسطه؛ دستورها در یک قالب کد می‌شوند:

ماشین صفرآدرسه (ماشین پشته‌ای)

در ماشین صفرآدرسه همهٔ عملوندها در یک پشتهٔ سخت‌افزاری داخل CPU نگه داشته می‌شوند.

پشتهٔ سخت‌افزاری یک حافظهٔ داخلی با S کلمه که برای نوشتن (push) و خواندن (pop) داده از راهبرد LIFO (آخرین ورودی، اولین خروجی) پیروی می‌کند. ثبات SP (Stack Pointer) به بالای پشته، یعنی جایی که آمادهٔ گرفتن دادهٔ جدید است، اشاره می‌کند.
  • push x: Stack(SP) ← x; SP ← (SP) + 1
  • pop: SP ← (SP) − 1 و کلمه‌ای که SP به آن اشاره می‌کند برگردانده می‌شود.

توجه کنید که در این قرارداد، SP به اولین خانهٔ خالی اشاره می‌کند؛ SP = 0 یعنی پشته خالی است. pop داده را پاک نمی‌کند؛ فقط SP را پایین می‌آورد (دادهٔ قبلی تا وقتی روی آن نوشته نشود باقی می‌ماند — این نکته در ماشین ۶ مهم است).

اجرای یک تابع در ماشین پشته‌ای

برای اجرای یک تابع مثل func(a,b)، عملوندهای a و b از بالای پشته برداشته می‌شوند و نتیجهٔ func(a,b) در پشته قرار می‌گیرد:

func  ==  pop  temp1
          pop  temp2
          temp3 ← func((temp1),(temp2))
          push temp3
مثال: add اگر پس از مثال بالا (پشته: −10، 100 و SP = 2) دستور add اجرا شود، دو عدد 100 و −10 برداشته و حاصل 90 در خانهٔ 0 قرار می‌گیرد و SP = 1 می‌شود. {{fig:stack_row([("before add",["-10","100","77"],2),("after add",["90","100","77"],1)], "اجرای add در ماشین پشته‌ای")}} برای اعمال غیرجابه‌جایی (تفریق و تقسیم) ترتیب مهم است: در این جزوه (و ماشین ۶) عملوند پایینی منهای/تقسیم بر عملوند بالایی حساب می‌شود؛ یعنی اگر اول a و سپس b در پشته گذاشته شود، sub مقدار a − b را می‌دهد.

نمادگذاری لهستانی و ماشین‌های پشته‌ای

نمادگذاری معمولی ریاضی میانوندی (infix) است: عملگر بین عملوندها می‌آید، مثل x + y یا z * t. اما نمادگذاری‌های دیگری هم وجود دارد:

  • پیشوندی (prefix): عملگر قبل از عملوندها: + x y یا * z t.
  • پسوندی (postfix) که نمادگذاری لهستانی (Polish notation) هم نامیده می‌شود: عملگر بعد از عملوندها: x y + یا z t *.
مثال اسلاید عبارت زیر را به نمادگذاری لهستانی بنویسید:

(x + y − 10 − t / d + 10*s − z) / (20*t − z / t + 100*w)

پاسخ

xy+10-td/-10s*+z-20t*zt/-100w*+/

نکات مثبت و منفی مثبت: (۱) نیازی به نگرانی دربارهٔ اولویت عملگرها نیست و پرانتز لازم نیست؛ (۲) برای محاسبه روی ماشین پشته‌ای بسیار مناسب است.
منفی: برای درک انسان مناسب نیست.

محاسبهٔ عبارت لهستانی روی ماشین پشته‌ای

روش: عبارت را از چپ به راست پیمایش کنید. اگر به عملوند رسیدید، آن را در پشته push کنید. اگر به عملگر رسیدید، آن را اجرا کنید (دو عنصر بالای پشته را بردارید و حاصل را push کنید).

در ماشین پشته‌ای، همهٔ دستورها (به‌جز push و pop) هیچ فیلد عملوندی در قالب دستور ندارند؛ بنابراین «تقریباً» همهٔ دستورها بدون فیلد عملوندند.

  • حافظهٔ اصلی 232 واحد آدرس‌پذیر ۸ بیتی؛ کلمه ۳۲ بیت؛
  • روش‌های آدرس‌دهی: ضمنی، مستقیم و بی‌واسطه؛ دستورها در دو قالب کد می‌شوند:

در دستورهای پرش، ابتدا شرط (مثلاً شمارنده) و سپس آدرس مقصد با push #label در پشته قرار می‌گیرد؛ دستور پرش هر دو را برمی‌دارد.

ترفند pop x و سپس sp++ ماشین دستور «کپی بالای پشته» (dup) ندارد. اما چون pop داده را پاک نمی‌کند، اگر بعد از pop x دستور sp++ بیاید، همان مقدار دوباره روی پشته برمی‌گردد. پس جفت pop x / sp++ یعنی «بالای پشته را در x ذخیره کن ولی آن را از پشته برندار».
مثال اسلاید: مجموع ۲۰ جملهٔ اول فیبوناچی در متغیر sum 
        org   0
loop:   push  x          ; [x]
        push  y          ; [x, y]
        add              ; [x+y]
        pop   x          ; x = x+y           []
        sp++             ; [x]   (مقدار جدید x دوباره روی پشته)
        push  sum        ; [x, sum]
        add              ; [x+sum]
        pop   sum        ; sum = sum + x     []
        push  x
        push  y
        add              ; [x+y]
        pop   y          ; y = x+y
        sp++             ; [y]
        push  sum
        add
        pop   sum        ; sum = sum + y
        push  counter
        push  #1
        sub              ; [counter-1]
        pop   counter    ; counter = counter-1
        sp++             ; [counter]
        push  #loop      ; [counter, loop]
        jnz              ; if counter≠0 goto loop
        push  #OS_return_addr
        j                ; بازگشت به سیستم‌عامل

sum:     dw  1
counter: dw  10

تبدیل عبارت میانوندی به پسوندی

الگوریتم اسلاید دو مرحله دارد:

  1. عبارت ورودی را کامل پرانتزگذاری کنید (هر عملگر با دو عملوندش یک جفت پرانتز بگیرد).
  2. از درونی‌ترین جفت پرانتزها شروع کنید و پرانتز راست را با عملگر آن جایگزین کنید و پرانتز چپ را حذف کنید.
مثال اسلاید: تبدیل عبارت (x + y − 10 − t/d + 10*s − z) / (20*t − z/t + 100*w)
مرحلهٔ ۱: پرانتزگذاری کامل 
(x+y-10-t/d+10*s-z) / (20*t-z/t+100*w)
((x+y)-10-(t/d)+(10*s)-z) / ((20*t)-(z/t)+(100*w))
(((x+y)-10)-(t/d)+((10*s)-z)) / (((20*t)-(z/t))+(100*w))
((((x+y)-10)-(t/d))+((10*s)-z)) / (((20*t)-(z/t))+(100*w))
(((((x+y)-10)-(t/d))+((10*s)-z)) / (((20*t)-(z/t))+(100*w)))
مرحلهٔ ۲: جایگزینی پرانتز راست با عملگر 
(((((x+y)-10)-(t/d))+((10*s)-z)) / (((20*t)-(z/t))+(100*w)))
(((( xy+ -10)- td/ )+( 10s* -z)) / (( 20t* - zt/ )+ 100w*))
((( xy+ 10- - td/ )+ 10s*z- ) / ( 20t* zt/- + 100w*))
(( xy+ 10- td/- + 10s*z- ) / 20t* zt/- 100w*+ )
( xy+ 10- td/- 10s*z- + / 20t* zt/- 100w*+ )
xy+ 10- td/- 10s*z- + 20t* zt/- 100w*+ /
نتیجه: xy+10-td/-10s*z-+20t*zt/-100w*+/
نکته: چرا این جواب با جواب قبلی کمی فرق دارد؟ در پرانتزگذاری بالا، +10*s − z به شکل +((10*s) − z) گروه شده است، در حالی که پرانتزگذاری استاندارد چپ‌به‌راست ((… + (10*s)) − z) است و جواب xy+10-td/-10s*+z-20t*zt/-100w*+/ (مثال قبل) را می‌دهد. چون a + (b − c) = (a + b) − c، هر دو عبارت لهستانی مقدار یکسانی دارند و هر دو درست‌اند. اگر بخواهید جواب یکتا باشد، همیشه عملگرهای هم‌اولویت را از چپ به راست گروه کنید.

روش دوم (تکمیلی): الگوریتم پشته‌ای

کامپایلرها معمولاً با یک پشتهٔ عملگر تبدیل را در یک پیمایش انجام می‌دهند (الگوریتم «ایستگاه قطار» دایکسترا): عبارت را از چپ به راست بخوانید؛ (۱) عملوند را مستقیم به خروجی بفرستید؛ (۲) برای عملگر، تا وقتی بالای پشته عملگری با اولویت بیشتر یا مساوی است آن را pop و به خروجی بفرستید، سپس عملگر جدید را push کنید؛ (۳) «(» را push کنید؛ (۴) با رسیدن به «)» تا رسیدن به «(» pop کنید؛ (۵) در پایان همهٔ عملگرهای پشته را pop کنید.

۱. عبارت (a + b) * (c − d) / e را به پسوندی و پیشوندی تبدیل کنید و آن را با a=2, b=3, c=7, d=1, e=5 روی ماشین پشته‌ای محاسبه کنید.

۲. عبارت پسوندی ab*cd*+e- را به میانوندی برگردانید.

حل با همان روش پشته‌ای ولی با ساختن رشته: a, b → a*b؛ c, d → c*d؛ + → (a*b + c*d)؛ e, − → a*b + c*d − e.

خلاصهٔ فصل ۳
  • ثبات = n فلیپ‌فلاپ با کنترل مشترک؛ PIPO/SIPO/PISO/SISO؛ فایل ثبات (یک دسترسی در هر لحظه) یا مجزا (موازی)؛ آدرس‌پذیر (R0…، AX…) یا غیرآدرس‌پذیر (MAR، MBR، IR، PC).
  • طول ثبات‌ها: MAR و PC به اندازهٔ آدرس، MBR به اندازهٔ پهنای دسترسی، IR به اندازهٔ بلندترین دستور.
  • روش‌های آدرس‌دهی این فصل: مستقیم، غیرمستقیم (یک/چند سطحی)، بی‌واسطه، شاخص‌دار و ضمنی.
  • بدون آدرس‌دهی غیرمستقیم می‌توان با کد خودتغییرده آرایه را پیمایش کرد (اما از دید مهندسی نرم‌افزار بد است).
  • اسمبلر دوگذره است (گذر ۱: جدول نمادها، گذر ۲: کد)؛ پیونددهنده ماژول‌ها و کتابخانه‌ها را ترکیب و جابه‌جا می‌کند؛ بارکننده برنامه را در حافظه می‌گذارد و اجرا می‌کند.
  • ماشین‌های ۳، ۲، ۱ و ۰ آدرسه؛ در ماشین پشته‌ای، عبارت‌ها به شکل لهستانی (پسوندی) و بدون پرانتز محاسبه می‌شوند.
